## 페이지 배치(패킹) — 절대 규칙

### ❌ 두 번 다시 하지 말 것 (실제로 실패한 방식)
1. **높이(mm·줄 수)를 추정해 페이지 배치를 계산하지 마라.**
   코드는 한글의 실제 렌더링 높이를 알 수 없다. 추정 패킹은 시험지마다
   과밀(한 단에 5문제)·overflow(보기·지문이 다음 단/페이지로 넘침)·빈 페이지를
   유발한다. (2026-06-28 실측 실패 — 광덕고/살레시오여고에서 배치 붕괴)
2. **pageBreak 를 명시적으로 넣지 마라.**
   신문형 2단에서 pageBreak 는 한글 자동흐름과 충돌해 배치를 망친다.
   원본 base.hwpx 는 pageBreak 가 **0개**다(증거: 한글로 만든 정상 시험지).
3. **높이(mm)를 추정해 columnBreak 위치를 계산하지 마라.** 추정 가변 배치는 한글 실측과
   어긋나 또 깨진다. (단, 아래 '2문제마다'처럼 높이와 무관한 고정 규칙은 OK.)
4. **keepWithNext 단독에 의존하지 마라.** 2026-06-29 실측: 문제 단락에 keepWithNext=1 을
   다 줬는데도 한글에서 메타↔본문, 본문↔그림이 페이지/단 경계로 **분리됐다**. keep 은
   '보험'일 뿐 실제 배치를 보장하지 못한다. 배치는 columnBreak 로 한다(아래).

### ✅ 올바른 방식 (현재 구현 = base.hwpx 원본과 동일한 메커니즘)
**검증된 사실(2026-06-29)**: 원본 base.hwpx 의 columnBreak 11개는 **전부 '문제 시작(메타)
단락 자신'에 붙어 있고**, pageBreak 는 0개다. 한글은 2단이 차면 자동으로 다음 페이지 1단으로
넘긴다. 이 메커니즘을 그대로 따른다:
- **2문제마다 '문제 시작(메타) 단락'에 columnBreak=1**(`i % 2 == 0 and i > 0`). → 단당
  최대 2문제 = **페이지당 최대 4문제**. 큰 문제는 둘째가 다음 단으로 자동 밀려 단당 1문제가
  된다(과밀·쪼개짐 없음). 이건 '높이 추정'이 아니라 '고정 규칙'이라 시험지마다 안 깨진다.
- **pageBreak 는 항상 0.** 페이지 나눔은 한글 자동흐름에 맡긴다.
- **보조로** 문제의 모든 단락에 keep paraPr: 메타/지문/보기=`KEEP_PARA_PR`(17, LEFT),
  그림=`KEEP_PIC_PARA_PR`(18, CENTER — 가운데정렬 보존). 그림 단락도 반드시 keep 체인에
  넣는다(안 그러면 지문↔그림 분리).
- 코드 위치: `build_exam()` 루프(메타단락에 columnBreak 설정),
  `assemble_hwpx._patch_header_keep()`(id=17/18 두 keep paraPr 주입),
  `assemble_hwpx.add_figure()`(그림단락 paraPrIDRef=18), `blocks.BODY_PARA_PR`(=17).
- ⚠️ `_patch_header_keep` 멱등 체크는 반드시 **`<hh:paraPr id="N"`** 로 한다. header 엔
  `charPr id="17"`·`borderFill id="17"` 이 별개로 존재하므로 `id="17"` 만 검사하면 오인
  skip 되어 paraPr 이 주입되지 않는다(2026-06-29 회귀 버그).

## 수식 변환(LaTeX→한글수식) — 절대 규칙
- `_extract_json`(vision_claude.py)에서 **전면 백슬래시 이중화 금지**. 모델이 JSON 문자열에
  LaTeX 를 단일 백슬래시(`\frac`, `\(`)로 넣으면 candidate 사다리로 [raw → LaTeX-aware 선택
  보정 → 이중백슬래시 정규화 후 보정] 순서로 파싱한다. 선택 보정 정규식:
  `\\(?!(?:["\\/]|u[0-9a-fA-F]{4}|[bfnrt](?![A-Za-z])))` — 유효 JSON 이스케이프(뒤에 영문자
  없는 \b\f\n\r\t 포함)만 보존하고 LaTeX 명령(`\f`rac·`\t`imes 처럼 이스케이프글자+영문자)만
  이중화한다. ❌ `body.replace('\\','\\\\')` 전면 이중화는 정상 `\n` 개행을 리터럴 `\n`으로,
  이미 이스케이프된 LaTeX 를 다중백슬래시(`\\frac`)로 파괴 → latex_to_hwp 가 못 알아봐 raw
  LaTeX·중괄호불균형이 그대로 노출됐다(2026-07-01 대량 버그, 재현·수정·검증 완료 OK 7/0).
- latex_to_hwp `_SIMPLE` 에 시험지 빈출 기호를 넣어둔다(□ square·△ triangle·∴ therefore·
  ∵ because 추가). 미지원 명령이면 ok=False → raw 텍스트 폴백된다.
- **치환 토큰은 반드시 앞 공백과 함께 삽입**(sqrt/root/left/right/rm/vec 등 영문자 시작 토큰).
  공백 없이 이어붙이면 직전의 미치환 명령과 붙어 가짜 명령이 된다:
  `q\pm\sqrt{37}` → `q\pmsqrt {37}` → "미지원 명령: pmsqrt" (2026-07-02 실사고).
- **위/아래첨자 인자는 반드시 중괄호로 감싼다**(`_brace_scripts`: `x^2`→`x^{2}`). 한글 수식은
  `^`/`_` 뒤 인자를 공백·중괄호 경계까지 **탐욕 흡수**한다 — `x^2+3x+2=0` 을 그대로 내보내면
  `2+3x+2=0` 전체가 위첨자로 렌더된다(2026-07-02 실사고, 하남중 1번 보기 전멸).
  base.hwpx 의 한글 저작 수식도 전부 `x^{2}` 꼴이다.
- **수식 객체 크기는 내용 근사치를 주입한다.** 한글은 hwpx 에 저장된 수식 `<hp:sz>`/baseLine 을
  열 때 **축소 재계산하지 않는다**(내용이 박스보다 크면 늘려 그리기만 함). 템플릿 수식의 고정
  3573×2415 를 그대로 복제하면 `x` 한 글자 수식 뒤 ~10mm 공백 + 수식 든 모든 줄의 줄간격 팽창.
  `set_equation_script` 가 `_eq_estimate_geometry`(assemble_hwpx.py)로 크기를 계산해 넣는다 —
  상수는 전부 base.hwpx 실측 수식 270개 역산값(실측 대조 폭 중앙값비 1.00, 높이/baseLine 오차 0).
  과소 추정은 안전(한글이 늘려 그림), 과대만 공백으로 남는다. 이건 '페이지 배치 추정 금지'
  규칙과 무관한 객체 자체 크기이며, 추정이 아니라 실측 역산이다.

  잡음), 상충 → 무보정. ±6° 하드바운드 + expand+흰채움(잘림 불가) — '페이지 자동 deskew
  금지' 규칙(90° 오판·내용 유실 사고)과는 무관한 크롭 단위 보정.
- ⚠ `add_figure` 는 **사본**(`deskewed_*.png`)만 만들고 원본 제자리 수정 금지 — 기하가 변해
  열려 있는 검수 UI 의 지우개 마스크 좌표가 어긋난다(whiten 은 색만 바꿔 제자리 OK).
  `deskewed_` 접두 파일은 재투입 시 무보정 가드가 있고 `_rehydrate` 글롭에도 안 걸린다.

## 그림 재작도 — 검증 게이트 (절대 규칙)
- Gemini image-to-image 재작도는 크롭 **가장자리의 읽을 수 없는 자국**(손글씨 풀이·점선 줄·
  잘린 글자)을 'ㄱㄴㄷㄹ…/ABCD…' 같은 **글자표로 환각 복원**해 그림에 넣을 수 있다
  (2026-07-02 실사고, 운림중 15번). 프롬프트 금지만으로는 부족하다.
- **`api_redraw` 는 재작도 직후 `verify_redraw`(opus)로 원본 대조**한다: ok=False 면 issues 를
  `redraw_with_gemini(feedback=)` 에 넣어 1회 재시도, 그래도 실패면 **반려**(HTTP 422, 그림은
  재작도 전 상태 유지, 결과 파일은 `rejected_*.png` 로 개명 보존 — 파일명 글롭 복구에 안 걸림).
- `_VERIFY_PROMPT` 는 '누락'뿐 아니라 **'추가 생성'도 탈락**시킨다(원본에 없는 글자 줄·범례·
  캡션·워터마크). 누락만 보던 종전 프롬프트는 글자표 추가를 82~95점으로 통과시켰다.
- **재작도 입력은 항상 `originals`(재작도 전 이미지)** — `j["figures"]` 가 redrawn_* 을 가리키면
  originals 로 바꿔 입력한다. 재작도본을 다시 입력하면 직전 환각이 누적된다('Pro 다시 생성'이
  종전엔 이 경로였음).
- `_encode_image`(vision_claude)는 media type 을 **매직바이트로 판별**한다. Gemini 가 JPEG
  데이터를 .png 로 저장하는 경우가 있어, 확장자 기반이면 Anthropic 400 → except 로 검증이
  통째로 스킵된다(이중 사고 방지).
