# AKP 운영 사용설명서 (학원장·관리자용)

한국 수학 시험지 PDF → HWPX 자동 변환 도구의 **운영자/관리자 매뉴얼**.

- **직원 단계별 사용법**(검수·수식 버튼판·그림 검수)은 앱 안의 **`/guide`** 페이지에 그림과 함께 정리돼 있습니다 — 직원에게는 그 페이지를 안내하세요. 이 문서는 그 위, **운영·관리·품질 개선 루프**를 다룹니다.
- **CLI/개발용 실행법**은 [USAGE.md](USAGE.md), **아키텍처**는 [PLAN.md](PLAN.md)를 보세요.

서비스 주소: **https://akp-production.up.railway.app**

---

## 0. 30초 요약

```
PDF 업로드 → (자동 OCR 변환) → 검수 보기에서 틀린 것만 고쳐 제출 → 검수본 HWPX 다운로드
                                              │
                            (고친 검수 전→후가 자동 기록)
                                              ↓
           관리자 화면 "반복 교정 분석"에서 반복되는 오류 확인 → 패턴 등록 한 번
                                              ↓
                       다음 변환부터 OCR이 같은 실수를 안 함 (자동 교정)
```

핵심 철학(반드시 기억): **사람이 매번 고쳐주는 구조가 아니라, 한 번 고친 걸 패턴으로 만들어 OCR 자체를 좋게 만든다.** 학원장 손은 "검수 한 화면"과 "가끔 패턴 승인"에만 둡니다.

## 1. 접속 · 로그인 · 역할

- 주소 접속 → **구글 계정으로 로그인**. 처음 쓰는 직원은 관리자가 먼저 등록해야 들어올 수 있습니다(2-1, 8-1 참고).
- 로그인하면 **작업 화면(매트릭스, `/matrix`)** 으로 들어갑니다.

### 역할(권한)과 볼 수 있는 단계

| 역할 | 표시 | 접근 STEP | 비고 |
|---|---|---|---|
| `tier1` | 기본 | STEP 1~4 | PDF·검수·한글완성본 |
| `tier2` | 그림완성 | STEP 1~4 | 기본과 동일 단계(그림 검수 담당) |
| `tier3` | 타이퍼 | STEP 1~5 | + 타이퍼 양식 |
| `tier4` | 해설 | STEP 1~6 | + 해설까지 전체 |
| `staff` | 직원 | STEP 1~6 | 전체 단계 |
| `admin` | 관리자 | STEP 1~6 + **관리자 화면** | 비용 무제한, 패턴 승인 |

> 역할은 **STEP 카드 접근 범위**를 정합니다. 직원에게 필요한 단계만 주면 됩니다. 비용 한도는 역할과 별개로 1인당 설정합니다(8-2).

## 2. 작업 화면(매트릭스) 읽는 법

위쪽에서 **연도 / 과목 탭**을 고르면, 아래에 그 과목의 **학교 목록**이 줄지어 나옵니다. 각 학교 줄은 **STEP 1~6 카드**로 진행 상태를 보여줍니다.

| STEP | 이름 | 의미 | 그 칸의 버튼(예) |
|---|---|---|---|
| 1 | **PDF** | 원본 시험지 | `재업로드` · `이동` |
| 2 | **HWPX 검수전** | 변환 직후 초안 | `다운로드` · `삭제` |
| 3 | **HWPX 검수완** | 검수 끝난 결과 | **`검수보기`** · `다운로드` |
| 4 | **한글완성본** | 타이핑 마무리본(직원 업로드) | `업로드` |
| 5 | **타이퍼 양식** | 2단 타이퍼용 | `자동 생성` · `업로드` |
| 6 | **해설** | 해설지 | `업로드` |

- 각 STEP 칸의 배지(`있음`/`완료`/`없음`)로 어디까지 됐는지 한눈에 봅니다.
- **새 변환의 시작점은 STEP 1에 PDF를 올리는 것**이고, **품질의 핵심은 STEP 3의 `검수보기`** 입니다.

### 2-1. 학교 추가 / 일괄 추가
- 과목 탭에 학교가 없으면 추가합니다. 한 번에 여러 학교를 넣는 **일괄 추가**도 있습니다(예: 51개 학교 초기 등록처럼 줄 단위로 학교명을 붙여넣기).

## 3. PDF 올려서 변환하기

1. 위에서 **연도·과목**을 먼저 고릅니다 → 파일 이름이 `[연도_학년_학기_a/b_과목약어_학교명]` 규칙으로 정해집니다.
2. 해당 **학교 줄 STEP 1**에서 PDF를 업로드(또는 그 줄에 끌어다 놓기)합니다.
3. **정답·해설까지 포함**해서 변환하려면 업로드 시 **"정답/해설 포함"** 옵션을 켭니다(문제만 필요하면 끕니다).
4. 변환이 도는 동안 진행 로그가 보입니다(보통 1~2분). 끝나면 STEP 2(검수전)가 **있음**이 됩니다.
5. STEP 3에서 **검수보기**로 들어갑니다.

> 💡 **누운(회전된) 시험지**는 자동으로 똑바로 돌려서 처리합니다. 보정본은 구글 드라이브 AKP 폴더에도 저장됩니다.
>
> ⚠️ **같은 PDF를 또 올리면 변환이 다시 돌아가 비용이 또 듭니다.** 한 번만 올리세요. 잘못 올렸으면 STEP 2 `삭제` 후 다시 올립니다.

### 3-1. 비용 한도
- 1인당 **일일 사용 한도(USD)**가 있습니다. 한도에 도달하면 변환이 막히고 "관리자에게 문의" 메시지가 뜹니다.
- **관리자는 무제한**입니다. 직원 한도는 관리자 화면에서 1인씩 조정합니다(8-2).

### 3-2. 같은 PDF 무과금 재변환(중요)
- **변환 결과(OCR 인식 마크다운 .md)** 만 있으면, Mathpix/Claude를 **다시 호출하지 않고**(재과금 0) 한글 파일을 다시 만들 수 있습니다.
- 변환/기록 화면의 **`OCR 기록(.md)`** 버튼으로 그 `.md`를 받아 둘 수 있습니다(7장).
- (CLI에서 재실행할 때는 `--pdf-id <이전_id>`로 Mathpix 재과금을 막습니다 — [USAGE.md](USAGE.md) 참고.)

## 4. 검수하기 (품질의 90%)

> 직원 단계별 설명(화면 보는 법, ✓정확/✎수정, 수식 버튼판, 🔴확인 필요)은 **앱 `/guide`** 에 그림과 함께 있습니다. 여기서는 운영자가 알아야 할 핵심만 정리합니다.

- **왼쪽 = 원본 시험지 이미지**, **오른쪽 = OCR이 읽은 문제 카드**. 카드의 수식은 **실제 모양으로 렌더**되어 보입니다(한글로 열 필요 없음).
- 문제마다 **✓정확** 또는 **✎수정**. 수정하면 편집 칸이 열립니다.
  - **"올바른 내용"** 칸을 고치면 → **최종 한글 파일에 반영**.
  - **"오류 메모"** 칸은 → **기록용**(본문 안 바뀜). 예: "분모에 f'(x) 빠져야 함".
- 수식은 타이핑 말고 **기호 버튼판**으로 넣고, **미리보기**로 확인합니다.
- 다 보면 맨 아래 **검수 완료 → HWPX 재생성**. 검수본(STEP 3)이 나오고 **재과금 0**으로 만들어집니다.

> 💡 **이제 메모를 안 적어도** 고친 내용은 자동으로 기록됩니다(6장). 다만 "왜 틀렸는지" 설명이 필요하면 메모도 같이 남기면 분석에 도움이 됩니다.

## 5. OCR 기록(.md) — 재과금 0의 베이스

- 변환이 끝나면 그 시험지의 **OCR 인식 결과 전체가 `.md`로 서버에 저장**됩니다.
- 변환 화면·기록표의 **`OCR 기록(.md)`** 버튼으로 내려받을 수 있습니다.
- 이 `.md`만 있으면 **언제든 무과금으로 다시 빌드/수정**할 수 있습니다 — 이게 "Railway 출력 베이스" 워크플로우의 핵심입니다.

## 6. ★ 품질 개선 루프 (이 도구의 심장)

검수에서 고친 내용을 **버리지 않고** OCR 개선에 재투입하는 자동 루프입니다.

```
검수에서 고쳐 제출
   │  (바뀐 문제마다 "검수 전(원본) → 수정 후" 가 자동 기록됨 — 메모 없어도)
   ▼
corrections.jsonl 에 누적
   │
   ▼
관리자 화면 "🔁 반복 교정 분석"
   ├─ 메모를 남겼으면 → 메모로 묶음 (예: "집합기호 없음 ×3")
   └─ 메모 없이 고쳤으면 → 내용 변화로 묶음 (예: "f'(x) → (삭제) ×3 · 시험지 2개에서")
   │
   ▼  반복되는 오류(2회 이상)에서 "패턴 등록" 클릭
prompt_patterns.json
   │
   ▼  다음 변환부터 OCR 시스템 프롬프트에 자동 주입
같은 학교/과목 시험지에서 같은 실수가 안 남
```

### 6-1. 무엇이 자동으로 되나
- **검수 제출 시**: 내용이 실제로 바뀐 문제마다 **검수 전 → 수정 후 전체가 자동 기록**됩니다(직원이 메모를 안 적어도). 원본 OCR 텍스트도 `original_text`로 보존되어 덮어써져 사라지지 않습니다.
- 그래서 **"메모만 봐야 하는" 한계가 없어졌습니다** — 실제 내용 변화 자체가 분석 대상이 됩니다.

### 6-2. 관리자가 하는 일 (가끔, 1분)
1. **관리자 화면(`/admin`) → "🔁 반복 교정 분석"** 패널을 봅니다.
2. **🔴 반복 오류 N종(우선 패턴화 권장)** 목록에서 같은 오류가 2회 이상, 특히 **시험지 여러 개에 걸쳐** 나온 것을 찾습니다.
3. 그 줄의 **`패턴 등록`** 을 누릅니다. 모달에 **원문/교정**이 미리 채워져 있습니다.
4. **적용 범위**를 고릅니다:
   - **전역(global)**: 모든 변환에 적용
   - **학교(school)**: 그 학교 시험지에만 (예: `상일여고`)
   - **과목(subject)**: 그 과목에만 (예: `미적분`)
5. 등록하면 **다음 변환부터** OCR 프롬프트에 자동으로 들어가 같은 실수를 막습니다.

> 패턴 승인은 **관리자(학원장)만** 합니다. 직원은 검수만 하면 되고, 그 결과가 자동으로 쌓입니다. **자동 적용이 아니라 "승인된 것만" 적용**되는 게 안전장치입니다.

## 7. 관리자 화면(`/admin`) 기능

상단 메뉴 또는 주소 `/admin`(관리자 권한 필요).

### 7-1. 사용자 · 역할 관리
- **사용자 추가**: 이름 · 구글 이메일 · 일일 한도(USD) · 역할 선택 후 등록.
- **역할 변경**: 각 사용자 줄에서 역할 드롭다운(기본/그림완성/타이퍼/해설/직원)으로 바로 변경.
- **일일 한도 변경**: 한도 값을 클릭해 인라인 수정. (관리자는 무제한)

### 7-2. 검수 수정 로그
- 누가 · 언제 · 어떤 시험지의 · 몇 번 문제를 · 무엇으로 고쳤는지 전체 기록.
- 직원별 통계, 기간/직원/키워드 필터.
- 잘못 들어간 항목은 **되돌리기**(reverted 처리 — 분석에서 제외됨).

### 7-3. 반복 교정 분석
- 6장의 루프를 보는 곳. **테마 칩**(집합/루트/분수 등 빈도)과 **반복 그룹**(메모/내용 기준)을 보여줍니다.
- 그룹마다 **시험지 N개에서** 배지가 붙으면 더 체계적인 오류 → 우선 패턴화.
- 각 그룹의 **`패턴 등록`** 으로 바로 승인.

### 7-4. 프롬프트 교정 패턴
- 승인된 패턴 목록. **활성/비활성 토글**, **삭제** 가능. 활성 패턴만 다음 변환에 주입됩니다.
- **기본 패턴 일괄 등록**: 도형·관계 기호(∠, △, ∽, ≡), 선분/벡터(\overline, \vec), 평행/수직(∥, ⊥) 같은 **검증된 큐레이션 패턴**을 한 번에 등록(멱등 — 중복 안 생김). 초기 품질을 빠르게 올리는 용도.
- **중복 정리(dedupe)**: 같은 잡·문제·메모·교정이 중복 쌓인 걸 정리.

## 8. 그림 검수 (그림 있는 시험지)

- 그림이 있는 시험지는 작업 화면 학교 줄에 **🖼 검수 N건** 배지가 뜹니다.
- 클릭 → 그림 검수 화면. 문제마다 **자동으로 잡은 빨간 박스**가 맞으면 **자동 선택**, 틀리면 **드래그로 영역 지정 후 수동 적용**, 그림이 아니면 **건너뛰기**.
- 다 했으면 **HWPX 반영** → 검수한 그림이 한글 파일에 들어갑니다.
- (정책: 신뢰도 임계값 등 내부 동작은 [PLAN.md](PLAN.md) 참고.)

## 9. 운영 정책 (절대 규칙)

도구가 이 전제로 설계됐습니다. 운영 시에도 지켜야 합니다.

1. **학교 단위 순차 처리** — 여러 학교를 동시에 병렬로 돌리지 않습니다.
2. **학원장 PDF 원본 = 진짜 정답** — OCR/LLM 결과보다 **원본 PDF가 우선**입니다. 검수 시 항상 원본과 대조.
3. **LLM은 패턴 발견기** — 자동 적용 금지. **승인된 패턴만** OCR에 주입됩니다(`temperature=0`).
4. **크롭 OCR 표준 순서** — 전체 OCR 후 공란을 발견해 통째로 재빌드하지 않습니다. 문제 단위 크롭 → 보정 → 1회 빌드.
5. **한 번에 최고 품질** — 중간 검수·재빌드 루프를 전제로 설계하지 않습니다. OCR 파이프라인 품질 자체가 전부.

## 10. 자주 묻는 것 · 문제 해결

| 증상 | 해결 |
|---|---|
| 메모만 적었는데 결과가 안 고쳐져요 | "오류 메모"는 기록용. 실제 수정은 **"올바른 내용"** 칸에서. (단, 메모 없이 본문을 고치면 자동 기록은 됩니다.) |
| 빨간 `【★ 확인 필요】`가 남아요 | OCR이 못 읽은 자리. 원본 보고 검수에서 채우세요. 안 채우면 한글 파일에 빨간 글자로 남습니다. |
| 같은 오류가 계속 나요 | 관리자 화면 **반복 교정 분석**에서 그 오류를 **패턴 등록**하세요. 다음 변환부터 안 납니다. |
| 비용이 또 나갔어요 | 같은 PDF를 또 올리면 재변환됩니다. **`OCR 기록(.md)`** 으로 무과금 재빌드하거나, CLI는 `--pdf-id` 재사용. |
| 직원이 로그인이 안 돼요 | 관리자 화면에서 그 이메일을 **사용자 추가**해야 합니다. |
| 변환이 안 끝나요/오류가 떠요 | 화면의 오류 메시지와 함께 관리자에게 알리세요. |
